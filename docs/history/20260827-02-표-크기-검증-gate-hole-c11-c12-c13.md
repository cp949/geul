## 목표

model의 표 크기 하한·상한 검증이 각자 다른 이유로 놓치던 gate hole 3건(architecture review candidate C11·C12·C13, 그릴링 완료 상태에서 착수)을 닫았다.

- C11: `validateGridCoverage`가 rowCount/columnCount의 정수·부호만 검사하고 0은 통과시켜, HTML import가 `<table></table>`(행 0개)로 0-row `TableBlock`을 만들면 model 검증 전체를 그대로 통과했다.
- C12: `validateTableSize`는 상한 두 비교뿐이라 NaN·음수·비정수 입력을 조용히 통과시켰다 — 내부 호출부 6곳은 전부 배열 `.length` 파생이라 태생적으로 안전했지만, model의 공개 export라 외부 소비자에겐 무방비였다.
- C13: `insertTable`은 하한(≥1)만 자체 검사하고 `model.validateTableSize`를 아예 호출하지 않아, 표 생성 경로만 `MAX_TABLE_COLUMNS`/`MAX_TABLE_LOGICAL_CELLS` 상한 밖이었다.
