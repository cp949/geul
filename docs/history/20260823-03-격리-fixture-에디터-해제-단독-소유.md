## 목표

## 바꾼 계약과 파일

- `packages/core/test/table-test-support.ts` — `createTableFixtureEditor`가 만든 에디터를 module-scope `Set<Editor>`에 자가 등록하고, `afterEach`가 참조하는 `destroyFixtureEditorsForTest`가 일괄 `destroy()`한다. 호출부는 더 이상 `.destroy()`를 직접 부르지 않는다. `destroy()`가 멱등이라 전환 중에도 이중 해제는 안전했다.
- `packages/core/test/table-test-support.test.ts` — 머리말(목적 선언·해제 책임 서술·"덮지 않는 것" 목록) 재작성, 정리 없이 끝나는 `it` 뒤에도 `afterEach`가 이미 해제했음을 단언하는 계약 테스트 추가, 자체 `editor.destroy()` 9곳 삭제.
- `table-commands.test.ts`(-45)·`table-paste-commands.test.ts`(-18)·`table-paste-validation.test.ts`(-10)·`table-keyboard-extension.test.ts`(-7)·`table-extension.test.ts`(-2) — 명시적 `editor.destroy()`/`outside.destroy()`/`inside.destroy()` 제거. `table-extension.test.ts`의 `emptyDocSchema` 경로를 쓰는 `it`(이중 해제 회귀 증거가 의존하는 대상)은 손대지 않았다.
- 공개 API 계약 변경 없음 — 전부 `packages/core/test/` 아래 테스트 헬퍼·테스트 파일이다.

## 남은 제한

- module-scope 소유 정리 훅(`Set` + 최상단 `afterEach`)이 `--no-isolate --no-file-parallelism` 조합에서 파일별로 무작위로 무효화된다. 이 변경이 새로 만든 위험이 아니라 `editor-controller-support.ts`(#91)에 이미 있던 패턴이고, 실제 검증 게이트(`pnpm verify`·CI)는 이 플래그 조합을 쓰지 않아 현재 영향은 없다.
- 정리 루프에 `try/catch`가 없어 하나의 `destroy()`가 던지면 나머지 정리가 스킵될 수 있다는 잠재 위험(관측된 실패 사례 없음, 하드닝 여지).

등록 기준(제품 동작·게이트 구멍·거짓 통과) 미달로 별도 이슈로 분리하지 않았다.
