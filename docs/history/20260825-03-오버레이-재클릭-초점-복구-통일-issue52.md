- `packages/react/src/table-handles.tsx` — `handleReorderHandleClick`/`handlePointerDownOnReorderHandle`에 같은 방식(`wasMenuOpenForHandleRef`)으로 대칭 수정.
- `packages/react/src/table-selection-toolbar.tsx` — 이미 목표 동작이라 무변경.
- `docs/guides/G-UI-001-build-dismissible-overlays.md` — "트리거 재클릭 = Escape와 같은 초점 복구 그룹" 구분 규칙 기록, "Escape만 초점을 복구한다"였던 모순 문구를 "Escape는 복구, 바깥 클릭은 유지"로 정정.
- `packages/react/test/block-side-menu.test.tsx`, `packages/react/test/table-handle-menu.test.tsx` — 재클릭 닫기 테스트를 `pointerdown → pointerup → click` 풀 제스처로 작성하고 `document.activeElement` 단언을 추가(G-TST-001). `block-side-menu.test.tsx`에 jsdom `setPointerCapture` 폴리필 추가.

## 남은 제한

- 열 핸들(column handle) 재클릭 닫기의 전용 unit 테스트가 없다 — `handleReorderHandleClick`이 `kind`로 행/열을 공유하는 같은 코드 경로라 행 핸들 테스트로 이번 MAJOR의 논리 결함은 잡히지만, 열 핸들만의 회귀는 별도로 잡지 못한다.
- Chromium e2e로 "재클릭이 닫는 분기를 탄다" 자체를 아직 직접 검증하지 않았다 — 이번 수정은 unit(jsdom) `fireEvent`의 `pointerdown/pointerup/click` 시퀀스로만 고정했다. 실제 Chromium이 같은 이벤트 배칭 특성을 보이는지는 실측하지 않았다.
- 위 두 잔여 위험은 등록 기준(제품 동작·게이트 구멍·거짓 통과) 미달로 별도 이슈로 등록하지 않았다 — `_works/20260825-03-issue52-overlay-retrigger-refocus/pending-issues/01.md`에 재검토 기록만 남겼다.
