## 바꾼 계약과 파일

- 루트·`apps/demo` 두 tsconfig(`tsconfig.configs.json`)를 신설해 세 config 파일을 `typecheck` 체인에 편입한다. 세 config 파일 자체의 내용은 바꾸지 않는다.
- 회귀 테스트의 typecheck 편입 계약을 "디렉터리마다 전용 tsconfig를 갖는다"에서 "추적 소스 파일 전량이 루트 `typecheck` 체인이 실행하는 프로그램의 컴파일 대상에 든다"로 바꾼다. `.js`/`.mjs`/`.cjs`/`.jsx`는 멤버십에 더해 그 프로그램의 `checkJs` 해석값이 `true`여야 커버로 센다 — `--listFilesOnly`가 import로 끌려온 파일도 담아, 멤버십만 세면 `checkJs: false`인 프로그램이 JS 소스를 과대평가하던 결함을 막는다.
- JS include 단언(`allowJs`/`checkJs`/`include`)의 입력을 디렉터리 열거에서 "체인 프로그램이 실제로 소유한 JS 소스" 기준으로 전환하고, 옛 디렉터리 발견 축(`trackedTopLevelSourceDirectories()`·`WORKSPACE_ROOTS` import·`trackedSourceFiles(directory)`)을 제거한다.
- `PIT-0016`·`INDEX.md`의 예방 규칙·요약을 파일 커버리지 단위 문장으로 갱신하고 "남은 사각지대"를 "닫힌 사각지대(Issue #105)"로 교체한다. `PIT-0015`의 인용 텍스트를 동기화한다.
- 결함 탐지(트랙-6)가 찾은 `segmentProjectPath()`의 중복 `-p`/`--project` 오분류(첫 매치가 아니라 실제 tsc처럼 마지막 매치를 채택하도록 수정, 오늘 트리엔 미발화)와, 이전 전 산출물의 작업 브랜치 해시·계획 문서 전용 식별자 참조(`PIT-0026` 위반)를 함께 정리한다.

## 남은 제한

- **루트 체인 추출 정규식이 `segmentProjectPath()`보다 엄격하다.** `chainTypecheckProjects()`의 정규식은 `tsc` 바로 뒤에 `-p`/`--project`가 와야만 매치한다. 발화 방향은 fail-loud(정규식이 프로그램을 놓치면 커버리지 테스트가 먼저 실패한다)이고, 오늘 15개 프로그램 전량이 `tsc -p <path>` 형태라 미발화다. 제대로 고치려면 프로그램 목록 평탄화 방식을 바꾸는 더 넓은 리팩터가 필요해 지금은 고치지 않았다.
- **`ownsCompiledJsSource()`/`coveredByChain()`의 `endsWith` suffix 매칭 오탐 가능성.** 이론적으로는 한 추적 경로가 다른 경로의 진짜 suffix가 되면 오탐할 수 있다. 오늘 추적 대상 확장자 파일 171개 전량 pairwise 대조로 오탐 쌍 0건임을 실측했다.

둘 다 등록 기준(제품 동작·게이트 구멍·거짓 통과) 미달로 별도 이슈로 분리하지 않았다.
