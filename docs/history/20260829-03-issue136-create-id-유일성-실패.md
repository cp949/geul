# Issue #136 createId 유일성 실패를 유한 시간에 거절

- 레인: qq-workflow
- 구현 커밋: `3f36356`
- 대상 이슈: [#136](https://github.com/cp949/geul/issues/136) — 완료 댓글 등록 후 종료

## 목표

사용자 제공 `createId`가 유효하고 유일한 ID를 만들지 못할 때 `BlockIdExtension`의 동기 무한 루프와 `duplicateBlock`의 중복 ID 문서 손상을 제거한다.

## 변경

- `packages/core/src/document-id-factory.ts`: block·중첩 block·table column·row·cell identity를 수집하고 최대 100회 안에 model-valid·문서 전체 유일 ID를 발급하는 내부 helper를 추가했다.
- `packages/core/src/block-id-extension.ts`: 상한 없는 `while`을 제거했다. `nextState.doc`의 non-blockContainer identity를 먼저 수집하고 누락·중복·충돌 block ID만 재발급한다.
- `packages/core/src/editor-controller.ts`: `duplicateBlock`이 mutation 전에 문서 전체 ID 충돌을 검사한다. revision 포화 상태에서는 factory를 호출하지 않는다. `CreateEditorOptions.createId` 공개 주석에 factory의 유효성·유일성 의무와 두 보호 경로의 실패 계약을 명시했다.
- `packages/core/test/document-id-factory.test.ts`: 상수·빈 문자열·제어 문자 factory, table identity 충돌, DOM transaction 충돌, `replaceDocument` 정규화와 revision 포화를 공개 editor 조립 경로에서 검증한다.

## RED/GREEN과 리뷰

- 최초 RED는 기존 무한 루프에 진입해 `timeout 5s`의 exit 124로 종료됐다.
- 단계-3 리뷰에서 공개 주석 범위 과장, DOM block ID와 table identity 충돌, revision 포화 뒤 불필요한 factory 호출을 발견해 수정했다.
- 수정 중 `currentDocument` 기반 충돌 집합이 `replaceDocument`의 새 문서 ID를 이전 문서 ID와 오판하는 회귀를 RED로 확인했다. `nextState.doc`를 identity 권위로 바꿨다.
