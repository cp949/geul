# G-WKS-006 Chrome75 floor에서 미지원인 Web API를 자체 구현으로 메운다

- 상태: `ACTIVE`
- 적용 조건: Geul 자기 소스가 호출하는 Web API(런타임 API, 문법이 아님)가 ADR-0008의 Chrome75 floor에서 미지원일 때. core-js가 채우는 "디펜던시 런타임 API" 격차(ADR-0009)와 다르다 — 이 격차는 Geul 자신의 소스가 호출부라 사용처 위임 대상이 아니다. `packages/model/src/id-factory.ts`(Issue #121, `crypto.randomUUID` → `crypto.getRandomValues`)가 첫 사례다.

## 구현 규칙

- 대체 구현을 시작하기 전에 다음 근거를 확인한다: (1) 미지원 버전 — MDN·caniuse 등 공개 자료 또는 실측, (2) 대체 알고리즘의 표준 준수 근거 — RFC 등, (3) 실제 floor 브라우저(Chrome83 Docker 등)에서 대체 구현이 의존하는 하위 API가 동작하는지 실측.
- 공유 구현 위치는 소비하는 패키지 중 최하위 레이어(`model` 우선, 그다음 `core`)에 두고 상위 레이어가 import해 재사용한다 — 계층마다 별도 사본을 만들지 않는다(ADR-0002).
- 신규 npm 의존성 추가 여부를 판단 시점에 명시적으로 검토하고, 추가하지 않는 선택지를 우선 고려한다 — 추가하면 `AGENTS.md`의 의존성 추가 사전 고지·`dependency-licenses.md` 갱신 의무가 따른다.
- `pnpm check:escompat` 게이트가 대체 구현 코드 자체도 검사 대상으로 삼는다 — 대체 구현이 다시 Chrome75 미지원 문법·API를 쓰지 않는지 이 게이트로 확인한다.
- 회귀 테스트는 두 층을 모두 둔다: unit test(포맷·계약 유지)와 실제 floor 브라우저에서 대체 구현이 실제로 소비되는 e2e 시나리오 최소 1개.

## 완료 기준

- 대체 구현이 기존 계약(형식, 유일성 등 소비 측이 이미 의존하는 속성)을 깨지 않는다 — unit test로 판정.
- 실제 floor 브라우저 실행(Docker 등)에서 대체 구현 경로가 예외 없이 동작한다 — e2e로 판정, 대체 전 코드로는 같은 시나리오가 실패해야 한다(원 결함 재현).
- 원 API가 안전해지는 시점(floor 상향)에 이 대체 구현만 교체하면 원복 가능하다 — 소비 측 계약(함수 시그니처)은 그대로 둔다.
