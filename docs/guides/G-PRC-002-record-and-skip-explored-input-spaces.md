# G-PRC-002 전수·무작위 조사는 입력 공간을 기록하고 이미 돈 공간은 다시 돌리지 않는다

- 상태: `ACTIVE`
- 적용 조건: 변환·직렬화 변경의 전수 조사, 무작위 샘플 조사 또는 수정 전후 퇴행 탐색을 직접 하거나 subagent·다른 에이전트에 맡김

## 구현 규칙

### 입력 공간 정의

조사한 입력 공간은 다음 항목으로 정의한다. 하나라도 빠지면 다른 에이전트가 같은 공간인지 판정하지 못한다.

- 글자 집합
- 길이 범위
- 노드·mark 종류와 제외 규칙(예: 인접 같은 종류 제외)
- 건수
- 판정 기준(예: strict 내보내기 후 재가져온 글자·mark 비교)
- 비교 기준(수정 전 커밋)
- 소요 시간

### 기록 위치

- 수정한 소스 파일의 머리 주석에 정의와 결과 건수를 적는다.
- 대상 이슈의 완료 댓글에 같은 정의를 적는다. 후속 이슈로 넘기면 그 본문에 적는다.
- 하네스는 저장소 밖에 둔다([`G-PRC-001`](./G-PRC-001-keep-scratch-work-outside-the-repository.md)). 하네스가 사라져도 정의만으로 재현할 수 있어야 한다.
- 메모리, `_works/`, 대화는 기록 위치가 아니다. 다른 에이전트가 읽지 못한다.

### 착수 전 확인

- 조사를 시작하기 전에 이미 돈 공간을 찾는다. 대상 소스 파일의 머리 주석, 대상·후속 이슈 본문과 댓글(`gh issue view <번호> --comments`), 계획서의 `## 결정` 절을 본다.
- 정의가 같은 공간은 다시 돌리지 않는다.
- 새 공간은 글자 집합, 길이, 노드·mark 종류 중 하나 이상이 달라야 한다.
- 예외: 이전 조사 이후 조사 대상 코드가 바뀌었고 그 변경의 퇴행 확인이 목적이면, 수정 전·후 비교로 한 번 돌린다.

### 위임 프롬프트

subagent와 다른 에이전트(Codex 포함)는 메모리와 `_works/`를 읽지 못하고 이 세션의 대화도 모른다. 위임 프롬프트에 다음을 적는다.

- 이미 돈 입력 공간 목록과 "재실행 금지".
- 이번에 돌릴 새 공간과 상한. 전수는 길이 상한, 샘플은 건수 상한을 적는다.
- 예상 소요 시간. 넘기면 중단하고 보고하게 한다.
- 위 기록 위치에 결과를 적을 정의 항목.

### 동시 실행

- 병렬로 돌리는 조사는 읽기 전용만 허용한다. 파일을 쓰는 에이전트는 한 번에 하나만 띄운다.
- 에이전트마다 `mktemp -d`로 만든 별도 scratch 디렉터리를 쓴다. 같은 경로를 공유하면 출력이 덮어써진다.
- 입력 공간을 나눠서 준다. 같은 공간을 두 에이전트에 주지 않는다.
- 게이트(`pnpm verify:quick` 등)와 전수 조사를 동시에 돌리지 않는다. CPU 경합으로 시간 상한 테스트가 거짓 실패한다.
- 출력 파일은 동기 쓰기로 닫은 뒤 판정한다. flush되지 않은 부분 파일로 판정하지 않는다.

## 검증

- 조사를 마친 변경의 소스 머리 주석 또는 이슈 댓글에 입력 공간 정의 항목이 모두 있다.
- 위임 프롬프트에 이미 돈 공간 목록, 재실행 금지와 상한이 있다.
- 병렬 조사가 있었다면 에이전트별 scratch 경로가 다르고 입력 공간이 겹치지 않는다.

## 완료 기준

- 다음 에이전트가 기록만 읽고 어느 공간이 돌았는지, 어느 공간이 남았는지 판정할 수 있다.
