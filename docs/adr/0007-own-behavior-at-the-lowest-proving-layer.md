# 각 동작은 그것을 증명할 수 있는 가장 낮은 계층이 단독으로 소유한다

Geul은 증명 계층이 셋이다 — jsdom vitest 스위트(62파일 779테스트, 9.07초), Playwright 회귀 게이트(115테스트, 39.4초, chromium 83 + firefox 16 + webkit 16), 그리고 게이트 밖의 성능 기준선 프로젝트(2테스트). 테스트당 벽시계 단가는 jsdom 11.6ms 대 브라우저 343ms로 약 30배 차이인데, 어느 계층이 어떤 동작을 소유하는지 적힌 곳이 없었다. 그래서 예산이 비대칭으로 움직인다 — spec을 하나 늘리는 데는 근거가 필요 없고 줄이는 데는 조사 한 번이 든다. Issue #74는 코드·단언·커버리지를 하나도 바꾸지 않고 `trace` 설정 변경과 perf spec 분리 두 가지로 게이트를 66.0초(3엔진 117개)에서 38.2초로 되돌렸다. 선택지는 셋이었다: 규칙을 적지 않고 리뷰 때마다 되찾거나, `docs/pitfalls/`에 재발 방지 규칙으로 적거나, 계층 소유권 결정으로 적거나. 첫째는 #74가 되찾은 26.6초를 다음 슬라이스에 조용히 반납한다. 둘째는 문서 책임이 어긋난다 — pitfall은 "이렇게 하면 또 깨진다"를 소유하는데 여기서 필요한 것은 "무엇을 어디서 증명하는가"이고, 그 판단은 배경 없이 재구성되지 않는다(현재 `@core` 16개의 선정 이유는 `playwright.config.ts`의 "R1 완료 조건(AC-05) 핵심 시나리오" 주석 한 줄뿐이라 `e2e/tailwind-migration.spec.ts`가 0개인 것이 의도인지 누락인지 판정할 수 없다). 따라서 **각 동작은 그것을 증명할 수 있는 가장 낮은 계층이 단독으로 소유하고, 브라우저 계층은 자신이 가장 낮은 계층일 때만 동작을 담는다.** ADR 0002가 패키지 축에서 "동일 불변식을 여러 패키지가 다시 구현하지 않는다"를 정한 것과 같은 원칙을 증명 계층 축에 적용한 것이다. 최초 기록은 Issue #88이다.

이 결정의 방향은 실측이 한 번 뒤집었다. 아키텍처 리뷰 C4 카드는 원래 실제 마운트가 생기면 브라우저에만 있던 항목을 jsdom으로 내릴 수 있다고 봤는데, Issue #76이 실제로 해보니 반대였다. 그래서 이것은 "브라우저 테스트를 줄여라"가 아니라 "브라우저 테스트는 이것만 담는다"이고, 상한과 함께 **하한**을 갖는다.

## Consequences

- 브라우저가 가장 낮은 증명 계층인 경우는 여섯이다. **실제 레이아웃**(`getBoundingClientRect`, PIT-0011 뷰포트 클램프), **CSS 캐스케이드와 계산 스타일**(`toHaveCSS`, `getComputedStyle`), **네이티브 포인터 드래그와 합성 click**, **브라우저 HTML 파서와 표 그리드 구성 알고리즘**, **데모 앱 배선**(jsdom 계층에는 데모 앱이 존재하지 않는다), **엔진 간 구현 차이**. 반대로 명령 실행 후 모델 상태와 캐럿 이동·undo 단계 수는 `core`가, 문자열 in/out 순수 변환은 `io`가 소유한다 — 브라우저가 이것을 다시 단언하면 규칙 위반이다.
- 판정 기준은 **그 단언이 무엇에 의존하는가**이지 어떤 API를 호출하는가가 아니다. 브라우저 전용 API 출현 빈도는 대리 지표이고 실제로 오분류한다: `e2e/editor-round-trip.spec.ts`는 그 지표가 0인데도 브라우저의 표 그리드 구성 알고리즘(`table.rows`·`cell.rowSpan`·`tHead`·`tBodies`)으로 앵커 순서 역전 내보내기를 검증하고, `Save JSON`/`Import HTML`/`Export GFM strict` 버튼에서 컨트롤러를 거쳐 편집기까지 배선 전체를 탄다. 반대 방향의 오분류도 막아야 한다 — e2e spec은 예외 없이 `openDemo`로 데모 앱을 띄우므로, 데모 앱을 **거치는** 것과 데모 앱 배선을 **단언하는** 것은 다르다. 자격을 주는 것은 후자뿐이다. 따라서 이 규칙에 자동 게이트를 붙이지 않는다 — 밀도 임계값은 `editor-round-trip.spec.ts`를 삭제 후보로 만든다. 강제 수단은 새 e2e spec을 추가할 때 위 여섯 중 어디에 해당하는지를 이슈나 PR에 적는 것이 전부다.
- **하한이 있다.** e2e 개수를 0으로 미는 것은 이 결정의 방향이 아니다. `packages/react/test/table-selection-toolbar.test.tsx`의 잔여 6건은 jsdom에서 만들 수가 없다 — `CellSelection`을 만드는 경로 셋(DOM Selection, 트리플클릭, Shift+Arrow)이 전부 죽는다. 앞의 둘은 `prosemirror-view`의 `posAtCoords`가 jsdom에 없는 `document.elementFromPoint`를 불러 `TypeError`로 끝나고, Shift+Arrow는 레이아웃 rect에 기대는 `endOfTextblock` 때문에 `.selectedCell` 데코레이션이 0개로 남는다(Issue #76). 이 6건의 커버리지는 `e2e/table-cell-selection.spec.ts`와 `e2e/table-format.spec.ts`가 소유한다. 같은 이유로 `stubRect` 호출 20곳(`packages/react/test/` 4파일)이 jsdom의 레이아웃 부재를 손으로 메우고 있고, 이것도 사라지지 않는다.
- `@core` 부분집합의 자격은 **엔진 간 구현이 갈릴 수 있는 시나리오**다. firefox·webkit 프로젝트가 `grep: /@core/`로 이 부분집합만 돌고 전체 회귀는 chromium이 단독으로 담당하므로, 태그가 없는 시나리오는 엔진 차이가 드러나지 않는다. 현재 16개는 이 기준으로 재판정된 적이 없다 — R1 완료 조건(AC-05)의 슬라이스 대표 시나리오로 골라졌다. 확인된 불일치는 `e2e/tailwind-migration.spec.ts`이고(4건 전부가 `getComputedStyle` 3회와 `getBoundingClientRect` 1회로 CSS 캐스케이드 결과와 실제 레이아웃만 검증하는데 `@core`가 0개다), 재판정은 이 ADR이 아니라 Issue #89가 소유한다.
- 중복이 발견되면 **낮은 계층을 남기고 브라우저를 지운다.** 단 게이트 개수가 줄어드는 변경은 사용자 승인 사항이다(`AGENTS.md`: 기존 테스트를 삭제하거나 assertion을 약화해 통과시키지 않는다). 이 규칙의 첫 적용 대상은 `e2e/table-keyboard-navigation.spec.ts` 4건이다 — 위 여섯 중 어디에도 해당하지 않고, `packages/core/test/table-keyboard-extension.test.ts` 7건의 진부분집합이다(jsdom 쪽만 표 밖에서 아무 것도 하지 않고 `false`를 반환하는 경우를 갖는다). 실행은 이 ADR과 분리한다 — 지우고 나서 지운 것을 정당화하는 규칙을 쓰면 규칙이 근거를 잃는다.
- `perf` 프로젝트는 이 규칙의 적용 대상이 **아니다.** `e2e/table-performance.spec.ts`는 회귀 게이트가 아니라 기준선 기록이라 `workers: 1`로 격리돼 `pnpm verify` 밖에 있고, 게이트 세 프로젝트가 `testIgnore`로 배제한다. 반대로 이 때문에 e2e 파일을 건드릴 때는 `pnpm test:e2e:perf`를 따로 돌려야 깨짐이 드러난다 — `pnpm verify`가 초록이어도 이 프로젝트는 검증되지 않았다.
- 이 결정은 `playwright.config.ts`를 바꾸지 않고 `@core` 태그를 옮기지 않는다. 계층 소유권만 정한다. 설정을 바꿔야 한다는 결론이 나오면 근거를 이 문서에 추가하고 실행은 별도 이슈로 뗀다.
- 본문 수치는 `fd3dd2f` 시점 실측이다 — `pnpm test:e2e` → `115 passed (39.4s)`, `pnpm test` → 62 files / 779 tests / 9.07s, `grep -c '@core' e2e/*.spec.ts` 합계 16, `e2e/*.spec.ts` 12파일 / `test()` 85건. 인용하기 전에 다시 재고 낡았으면 갱신한다. 이 결정의 근거가 계층 단가의 30배 비대칭이므로, 비대칭이 사라지면 결정 자체를 다시 본다.
