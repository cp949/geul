슬라이스 7부터 `EDITOR_FEATURE_UNAVAILABLE` 게이트가 두 방향으로 분리됐고(사용자 승인 결정), **슬라이스 12가 남은 로드 방향 차단을 해제해 게이트가 완전히 사라졌다.** 표 명령이 `EditorController`에 연결되고 Table 확장이 라이브 에디터 스키마에 등록되어 에디터 안 표 편집·`getDocument()` 저장이 동작하며(`TBL-002`/`TBL-003`/`TBL-004`/`TBL-005`/`TBL-009`는 `VERIFIED`), 슬라이스 12부터 **표가 든 문서의 로드**(`createEditor` 초기 문서, `replaceDocument`)도 동작한다 — `model-to-tiptap.ts`가 표 블록을 tiptap JSON으로 인코드하고(`tableBlockToTiptapJson`, G-TBL-001 열 재정렬 포함, 표 코덱과 공유), 셀 콘텐츠는 문단과 같은 `inlineContentViolation` 계약으로 로드 경계에서 검증된다. `EDITOR_FEATURE_UNAVAILABLE` 에러 코드는 생산처가 사라져 공개 `EditorError` union에서 제거됐다(`BLK-012`는 `VERIFIED`). 슬라이스 11부터 클립보드를 통한 표 붙여넣기(`TablePasteExtension`, `pasteTabularData`)는 표 노드로 파싱된다(`TBL-012`/`TBL-013`/`TBL-014`는 `VERIFIED`) — 이 경로는 `core`가 새로 의존하는 `io`의 HTML sanitizer·테이블 변환기(`TabularData`/`ClipboardTableParser`)를 거쳐 정규화된 id로 표를 만들므로 이전에 우려했던 문서 검증 영구 실패 없이 열 수 있다. 슬라이스 8은 셀 범위 선택·병합·분할을 완성했고, 슬라이스 9a는 행/열 핸들 메뉴·헤더·색상·삭제를 완성했으며, 슬라이스 9b는 `TBL-007`·`TBL-008`을 완성했다. 세부 계약과 구현 결정은 [Issue #3](https://github.com/cp949/geul/issues/3)과 [R1 spec](../specs/2026-08-14-tiptap-block-editor-mvp-design.md)이 소유한다. 슬라이스 13은 `playwright.config.ts`에 `firefox`/`webkit` 프로젝트를 추가하고 `@core` 태그가 붙은 핵심 시나리오 16개만 그 두 엔진에서, chromium에서는 전량(70개+)을 돌리는 방식으로 구현했다. Firefox 합성 `ClipboardEvent` 결함의 근본 원인·수정 방식은 `G-TST-001`이 원본이고, R1 완료 판정 근거(항목별 판정, 발견 결함, 재검토·수정 이력)는 [`r1-enhanced-table-mvp-completion.md`](../reviews/r1-enhanced-table-mvp-completion.md)가 원본이다(`R1-01`·`R1-02` 회차, 5개 조건 전부 `PASS`) — 이 문서에 복제하지 않는다.

R1 완료 뒤 이어진 아키텍처 리뷰(4차, 카드 U)가 `model`의 `parseDocument` 결함을 하나 고쳤다 — 표 크기 상한 판정이 논리 셀 수(`rowCount*columnCount`)만 보고 열 수 자체(`MAX_TABLE_COLUMNS`)는 검사하지 않아, 행이 0개인 열-편중 표(예: 행 0·열 50000)가 HTML import·클립보드 붙여넣기 경로에서는 거절되면서도 저장 문서 로드 경로에서는 통과하는 진입 경로별 불일치가 있었다. `validateTableLimits`가 다른 경로와 같은 권위(`validateTableSize`/`tableSizeViolationMessage`)를 쓰도록 교체해 판정을 하나로 모았다. 코드 정리를 넘는 동작 변경이지만(로드 시 새로 거절되는 입력이 생김), 전 패키지가 미배포·비공개(`0.0.0`, `private`)라 영향받는 기존 저장 데이터는 없다.

R2는 `model`의 `Block` 공통 `children?: Block[]`로 문서를 재귀 트리로 재설계했다(슬라이스 1, 깊이 상한 64). H4-H6·토글 제목·인용문·구분선·코드 블록과 글머리·번호·체크·토글 목록 4종이 신규 블록 타입으로 추가돼 `BLK-003`~`BLK-011`이 `VERIFIED`다(`BLK-005`는 예외, 아래). 다중 블록 선택·이동·삭제(`UI-004`), 인라인·블록 글자색/배경색/정렬(`INL-008`~`INL-011`), 신규 블록 타입 전체의 placeholder(`UI-009`)와 trailing block(`UI-010`), BlockNote 기본 키보드 단축키·입력 규칙 재확인 구현(`UI-011`), 일반 clipboard HTML/Markdown/plain text 우선순위 fixture(`IO-007`)를 완료했다. 슬라이스 11이 Chromium/Firefox/WebKit 3-엔진 `@core` 게이트를 슬라이스 1~10 대표 시나리오로 확장하고(roadmap-workflow RD-001) R2 완료 판정을 마쳤다(RD-002). `IO-007`(파일 붙여넣기 부분, spec 2.2)과 `BLK-005`(인용문 GFM 중첩 표현 재평가 미해결, 2026-09-04 사용자 승인 이월)는 후속 이슈로 추적하는 계획된 `PARTIAL`로 남는다. 세부 구현 결정과 슬라이스별 이력은 Issue #38, R2 완료 판정 근거(항목별 판정, 계약 변경 이력)는 [`r2-basic-block-parity-completion.md`](../reviews/r2-basic-block-parity-completion.md)가 원본이다 — 이 문서에 복제하지 않는다.

`TableGrid.pasteInto`/`pasteTabularData`/`TablePasteExtension`은 `core`가 소유한다. `pasteInto`는 새 겹침 탐지 로직을 만들지 않고 기존 `validateTableGrid`를 재사용해 구현했고(확장은 최초 `insertRow`/`insertColumn` 반복 삽입에서 이후 리뷰-수정 세션에서 덮어쓰기 사각형 밖 좌표만 채우는 단일 패스 벌크 생성으로 교체됨), `model`의 그리드 커버리지 검증을 `validateGridCoverage`로 제네릭화해 `TableBlock` 검증과 `TabularData` 검증이 같은 함수를 공유한다. 클립보드 HTML의 인라인 style(color/background-color/text-align)을 읽어 셀 서식을 복원한다. 이 style 파싱은 클립보드 경로 전용이며 sanitize 스키마도 `clipboardSanitizeSchema`로 분리해 `importHtml` 동작을 바꾸지 않는다 — 최초 구현은 공유 스키마의 td/th 허용 목록에 `style`을 넣어 `importHtml`이 여전히 무시하는 속성의 `UNSAFE_ATTRIBUTE_REMOVED` 경고를 사라지게 만들었고, 2차 리뷰에서 이를 발견해 스키마를 분리했다. 이 변경으로 외부 HTML 표 붙여넣기가 표 노드로 파싱되도록 계약이 바뀌어(기존 '파싱 안 됨' 계약을 교체) `packages/core/test/editor-controller-table.test.ts`와 `e2e/table-handle.spec.ts`의 관련 테스트를 각 1건씩 교체했다. Issue #12(`io` 10,000셀 markdown 테스트 타임아웃)는 진단 결과 실제 파서 성능 문제(micromark-extension-gfm-table의 `EditMap.addImplementation`이 셀당 누적 edit map을 선형 스캔)로 확정했고, 병목이 서드파티 `remark-gfm` 내부라 이 슬라이스 범위에서는 테스트 타임아웃을 20,000ms로 조정해 안정화했다(서드파티 패치는 후속 이슈로 제안). spec 13 성능 기준선을 `docs/product/performance-baseline.md`에 최초 기록했다(TSV 100×100, 로컬 Chromium: 붙여넣기 2066ms, 선택 5312ms, undo 184ms). 슬라이스 12는 `model-to-tiptap.ts`의 표 차단 분기를 제거하고 표 블록 → tiptap JSON 인코더(`tableBlockToTiptapJson`)를 추가했다 — G-TBL-001 열 재정렬을 포함하며, 표 코덱(`tableBlockToTiptapNode`)이 이 인코더를 `schema.nodeFromJSON`으로 재사용해 로드/붙여넣기 매핑이 한 곳에서 관리된다. 셀 콘텐츠는 문단 로드·표 붙여넣기와 같은 `inlineContentViolation` 계약을 로드 경계에서 적용한다(빈 텍스트 런·미지원 링크는 `DOCUMENT_INVALID`). 생산처가 사라진 `EDITOR_FEATURE_UNAVAILABLE`은 공개 `EditorError` union에서 제거했고, demo 앱의 detached-document 우회(차단된 표 문서를 export하기 위한 장치)도 함께 제거했다. R0의 표 거절 회귀 테스트는 로드 허용·round-trip 테스트로 교체했다(unit 6건, e2e 2건 전환 — 열 너비 저장 후 로드 복원, 병합 표 HTML import의 에디터 로드). 슬라이스 13은 3-엔진 게이트와 R1 완료 판정을 마쳤다(위 절과 [`r1-enhanced-table-mvp-completion.md`](../reviews/r1-enhanced-table-mvp-completion.md) 참고). 이 판정 과정에서 `INL-001`(일반 텍스트)이 R0부터 실질 동작 중임에도 인벤토리에 `NOT_STARTED`로 남아 있던 것을 발견해 `VERIFIED`로 교정했다.

각 슬라이스는 회귀 테스트를 먼저 추가해 RED를 확인한 뒤 최소 구현으로 GREEN을 만들고, 슬라이스별 완료 기준과 검증 명령을 충족한 뒤 다음 슬라이스로 넘어간다.

R1 vertical slice 순서, 책임 경계와 확정 사항은 Issue #3이 원본이며 이 문서에 복제하지 않는다.

## 운영 경계

- 현재 문서는 다음 제품 작업의 진입점을 지정하며 구현 계획을 대신하지 않는다.

- commit, merge, push, publish와 PR 생성의 승인 경계는 `AGENTS.md`의 "공통 규칙"이 소유한다. GitHub 이슈·댓글 등록은 `docs/agents/issue-tracker.md`의 "게시 승인"을 따른다.
- 프로젝트 자체 배포 라이선스 결정은 공개 배포 전 [GitHub Issue #2](https://github.com/cp949/geul/issues/2)에서 수행한다.
