# PIT-0030 PIT-0026 위반을 서술할 때도 해시 값 자체는 인용하지 않는다

- 상태: `ACTIVE`
- 적용 영역: git·process
- 최초 근거: PIT-0026 위반 정정 중(ff-workflow 트랙-5)

## 상황과 징후

트랙-5가 작업 폴더 전량 `grep`으로 `PIT-0026` 위반(작업 브랜치 커밋 해시가 이전 전 산출물에 남은 경우)을 찾아 원본(`_meta.md` 등)에서 지웠다. 그 직후 "무엇을 발견해서 어떻게 고쳤는지"를 `IMPL-REVIEW-NN.md`의 발견/수정 절과 체크리스트 판정 문장에 근거로 남기면서, 지워야 할 해시 값을 예시로 다시 인용했다(예: "해시 4개(`03660cf`·`a1b2c3d`·…)가 있었다") — `PIT-0026`이 겨냥하는 바로 그 패턴이 finding 서술 안에서 그대로 되살아났다. 재실행한 전량 sweep으로만 드러난다.

## 근본 원인

`PIT-0026`의 예방 규칙은 "DELTA 완료 로그에 해시를 적지 않는다"는 **1차 서술 행위**를 겨냥한다. 이번 재발은 **위반을 진단·수정하는 2차 서술 행위**(finding 근거, 판정 각주)에서 일어났다 — 원 규칙이 예상하지 못한 경로다. "지운 것을 증명하려면 무엇을 지웠는지 보여줘야 한다"는 직관이 해시 재인용을 자연스럽게 만든다.

## 예방 규칙

- `PIT-0026` 위반을 finding으로 서술할 때 그 위반 해시 값을 인용하지 않는다. "DELTA당 1개씩 작업 브랜치 커밋의 짧은 해시를 인용했다"처럼 값 없이 서술하거나, 굳이 예시가 필요하면 `<해시>`처럼 명백한 플레이스홀더를 쓴다 — hex처럼 보이는 임의 문자열은 다음 sweep에서 다시 매치돼 노이즈가 된다.
- `PIT-0026` 위반을 수정한 뒤, 그 수정을 서술한 산출물(`IMPL-REVIEW-NN.md`, 체크리스트 판정) 자체를 포함한 범위로 같은 sweep을 한 번 더 돌린다 — 원본 수정 확인과 별개로, 방금 쓴 리뷰 문서도 대상에 넣어야 한다.

## 검증 방법

`PIT-0026` 위반을 수정한 직후 실행하는 sweep을, 그 수정을 서술한 산출물까지 포함한 범위로 한 번 더 돌린다.

```bash
grep -rnoE '`[0-9a-f]{7,40}`' <작업 폴더>/
```

`dev` 조상 커밋(브랜치 분기점, 이미 병합된 과거 완료 커밋) 외의 매치가 남으면 재발이다.

## 실제 근거

- 2026-08-24 작업 `20260824-02-issue16-23-28-table-command-hardening` 트랙-5 — 트랙-4 진행 로그가 남긴 작업 브랜치 해시 4개를 걷어낸 직후, 그 걷어낸 사실을 서술한 판정 문장에서 같은 해시 값이 재인용된 것을 재실행 sweep으로 발견해 다시 정정했다.
