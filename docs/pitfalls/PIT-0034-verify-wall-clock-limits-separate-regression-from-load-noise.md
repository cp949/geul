# PIT-0034 wall-clock 상한이 회귀와 부하 잡음을 가르지 못할 수 있다

- 상태: `ACTIVE`
- 적용 조건: 복잡도 회귀를 시간 상한(`toBeLessThan`, timeout)만으로 게이트
- 정상 가이드: [`G-TST-004`](../guides/G-TST-004-test-complexity-deterministically.md)
- 최초 근거: Issue #58 (PIT-0018 후속)

## 오해하기 쉬운 신호

`pnpm test`(모노레포 동시 실행) 부하 상태의 **정상 코드** wall-clock 실측이 **회귀 코드**의 무부하 실측과 겹칠 수 있다 — 단독 실행에서는 안정적으로 통과하다가 동시 실행에서만 간헐 실패하고, 상한을 올리면 이번엔 회귀 자체가 상한 아래로 숨는다.

## 원인과 회피

측정된 wall-clock은 알고리즘 비용, 무관한 고정 비용, 동시 실행 중인 다른 프로세스와의 코어 경쟁의 합이라 단언이 셋을 구분하지 못한다. 시간 상한을 추가하기 전에 정상 코드의 부하 분포와 회귀 코드의 무부하 분포가 겹치는지 확인한다.

두 분포가 겹치면 시간 단언만으로는 회귀와 부하 잡음을 구분할 수 없다. 이때의 대응은 정상 가이드 `G-TST-004`의 결정적 작업량 규칙을 따른다. 특정 환경에서 측정한 배수는 관련 Issue나 성능 review에 남기고 공통 규칙으로 승격하지 않는다.

## 탐지

```bash
grep -rnE "toBeLessThan\(.*(TIME_LIMIT|LIMIT_MS)|performance\.now\(\)|[Tt]imeout" packages/*/test/
```

새로 거는 시간 상한마다 정상 부하 분포와 회귀 무부하 분포의 겹침을 확인한 근거 주석이 있는지 확인한다. 이미 구조적 제약(예: 표 최대 셀 수)으로 입력 크기가 고정돼 병목을 실제로 제거할 수 없는 경우의 시간 상한은 예외로 허용한다.
