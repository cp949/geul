# PIT-0026 이전 전 산출물에 작업 브랜치 커밋 해시를 적지 않는다

- 상태: `ACTIVE`
- 적용 영역: git·process
- 최초 근거: Issue #107

## 상황과 징후

ff-workflow의 트랙-4는 DELTA를 하나 끝낼 때마다 진행 로그에 완료 사실을 적는다. "커밋했다"를 적을 때 그 커밋의 짧은 해시를 함께 적는 것이 자연스러운 표기다.

```
... 검증 명령 전부 통과. 커밋 `03660cf`(작업 브랜치, push 안 함).
```

아무것도 실패하지 않는다. 트랙-8이 커밋을 재그룹화하는 순간 그 해시들이 전부 도달 불가능한 객체가 되고, 남은 참조는 죽은 링크가 된다.

## 근본 원인

작업 브랜치 커밋은 트랙-8의 재그룹화(cherry-pick + 새 커밋)로 원래 해시를 전부 버린다. `dev`로 이전된 커밋은 새 해시를 갖고, 원본은 백업 ref를 지우는 순간 사라진다.

규칙 자체는 이미 있다 — [`../agents/ff-workflow.md`](../agents/ff-workflow.md)의 "커밋 해시 참조"가 "이전 전에는 이슈, 댓글, 초안과 어느 산출물에도 해시를 쓰지 않는다"를 소유한다. 재발하는 이유는 규칙이 없어서가 아니라 **트랙-4가 그 절을 다시 읽지 않고 관성으로 적기** 때문이다. 규칙은 문서의 뒤쪽에 있고, 해시를 적는 순간은 DELTA 하나를 끝낸 직후다.

`dev` 자신의 기준선 해시는 이 규칙의 대상이 아니다. 재그룹화가 `dev`를 건드리지 않으므로 애초에 불안정하지 않다 — 규칙이 겨누는 것은 작업 브랜치의 커밋이다.

## 예방 규칙

- DELTA 완료 로그에 "커밋했다"를 적을 때 해시를 인용하지 않는다. "작업 브랜치에 커밋(push 안 함)"으로 적는다 — 어떤 커밋인지는 로그 항목의 위치와 날짜, `git log --oneline dev..<브랜치>`로 언제든 다시 찾을 수 있다.
- 절차 변경이나 사용자 개입을 로그에 남길 때도 커밋 메시지나 파일 경로로 가리키고 해시는 쓰지 않는다.
- `dev`의 고정 기준선 해시는 인용해도 된다.
- 확정 해시는 이전이 끝난 뒤 `_meta.md`의 "확정 커밋 해시" 절에 한 번만 기록한다.

## 검증 방법

트랙-7이나 트랙-8 진입 시점에 작업 폴더 전량을 훑는다.

```bash
grep -rnoE '`[0-9a-f]{7,40}`' <작업 폴더>/
```

트랙-0이 확인한 `dev` 기준선 해시 외에 매치가 남으면 작업 브랜치 커밋 해시가 섞여 든 것이다.

## 실제 근거

- 2026-08-23 Issue #107·#108 — 트랙-4가 DELTA 6개를 끝내며 진행 로그 6곳에 작업 브랜치 해시를 적었고, 계획 리뷰 산출물 1곳도 사용자 커밋을 해시로 인용했다. 트랙-5가 완료 체크리스트 항목("어떤 산출물에도 커밋 해시를 쓰지 않았다")을 판정하다 위 `grep`으로 7건을 찾아 걷어냈다. 재그룹화 후 그 7개 해시는 전부 도달 불가능해졌다.
