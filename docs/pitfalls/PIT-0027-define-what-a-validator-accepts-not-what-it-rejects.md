# PIT-0027 fail-loud 검증기는 거절할 것이 아니라 통과시킬 것을 정의한다

- 상태: `ACTIVE`
- 적용 영역: scripts·gate·test
- 최초 근거: Issue #107

## 상황과 징후

게이트의 검사 범위나 입력 형태를 검증하는 코드를 "잘못된 것이 오면 시끄럽게 죽는다"로 만든다. 거절 사례를 몇 개 골라 테스트에 넣고 전부 거절하는 것을 확인한다. 그 시점에 검증기는 의도대로 동작하는 것처럼 보인다.

징후는 없다. 이 실패는 조용하다 — 검증기가 통과시킨 값이 아래로 흘러 최종 관측값을 0으로 만들고, 게이트는 exit 0으로 끝난다.

`scripts/workspace-roots.mjs`가 workspace glob을 `<이름>/*`만 받도록 만들었을 때 통과 조건은 이렇게 적혔다.

```js
const singleSegmentGlobPattern = /^([^/]+)\/\*$/;
```

이름 세그먼트를 "슬래시를 포함하지 않는 임의의 앞부분"으로 정의한 그 문장이 glob 메타문자를 이름으로 받는다.

```
"apps/**"           THROW
"!packages/legacy"  THROW
"*/*"               ACCEPT root="*"     ← pnpm이 정상 해석하는 glob
"**/*"              ACCEPT root="**"
```

`resolve(repoRoot, "*")`는 `*`라는 이름의 디렉터리 리터럴을 가리키고 트리에 없다. 바로 아래 `existsSync` 가드가 그것을 조용히 건너뛴다.

```console
$ node scripts/check-licenses.mjs
License allowlist verified across 0 manifests and 1 external transitive production packages.
$ echo $?
0
```

검증기가 존재하는 이유("감시 범위가 조용히 좁아지는 것을 막는다")에 해당하는 실패가 검증기를 통과한 채 그대로 일어난다.

같은 형태가 경계 판정에서도 나온다. `tests/workspace-roots.test.ts`의 매니페스트 파서가 `packages:` 목록의 끝을 "들여쓰기 없는 다음 줄"로 정의했는데, 목록 **중간의 들여쓴 주석 줄**이 그 조건에 걸려 뒤 항목이 통째로 버려졌다. 잘린 목록이 마침 모듈 리터럴과 같으면 대조가 통과하고, 매니페스트가 선언한 새 루트가 모든 게이트 밖으로 빠진다.

## 근본 원인

검증기를 **거절 목록**으로 설계했다. 이중 별, 부정 접두, 추가 세그먼트, `./` 접두 — 그 넷을 거절하는지 확인했고 실제로 거절한다. 확인하지 않은 것은 통과 조건이 무엇까지 받아들이는가다. `[^/]+`는 거절 목록에 없던 모든 것을 받고, 그 안에 원래 막으려던 대상이 들어 있었다.

거절 목록으로 검증기를 검증하면 이 갈래가 구조적으로 보이지 않는다. 테스트도 같은 목록에서 나오기 때문이다 — `it.each(["apps/**", "apps", "!packages/legacy", "apps/**/*", "./apps/*"])`. 다섯 개 전부 통과하고, 통과 조건의 나머지 면적은 아무도 보지 않는다.

여기에 관용적 처리가 겹쳐 침묵이 완성된다. `existsSync` 건너뛰기 자체는 옳다 — 매니페스트가 선언한 루트가 트리에 아직 없을 수 있고, 그때 `readdirSync`가 ENOENT로 죽으면 게이트가 검사 실패가 아니라 크래시로 끝난다. 문제는 **형태 검증을 통과한 쓰레기 값**이 그 가드에 도달한다는 것이다. 형태 검증이 느슨하면 그 아래의 모든 관용적 처리가 침묵의 통로가 된다.

## 예방 규칙

- **"X가 아니면 throw"가 아니라 "정확히 Y만 통과"로 적고, Y를 문자 집합 수준까지 좁힌다.** 이름 세그먼트는 "슬래시 없는 임의 문자열"이 아니라 디렉터리 이름 리터럴이다 — glob 메타문자(`* ? [ ] { } ! ( ) + @`)를 통과 조건에서 뺀다.
- **검증기 테스트에 "막으려던 대상 자신"을 넣는다.** 검증기가 존재하는 이유를 한 문장으로 적고, 그 문장에 해당하는 입력을 전부 나열한다. 거절 사례를 다섯 개 적고 끝내지 않는다.
- **통과 조건을 넓게 두고 뒤에서 관용적으로 처리하지 않는다.** `existsSync` 건너뛰기, `?? 기본값`, 옵셔널 체이닝은 형태 검증을 통과한 값에만 적용한다.
- **경계 판정에서 "끝"을 정의할 때 중간에 낄 수 있는 것을 먼저 센다.** YAML 목록의 끝을 판정한다면 빈 줄, 주석 줄, 들여쓰기 변화가 항목 사이에 낄 수 있다. 그 셋을 세지 않은 "끝" 정의는 목록을 조용히 자른다.
- **파생과 검증이 같은 술어를 쓰게 한다.** 파생 쪽이 `glob.split("/")[0]`으로 따로 갈리면 형태 검증이 한쪽에만 걸리고, 잘못된 값이 파생을 통해 다른 경로로 새어 나간다.
- **판정 술어 자체를 참조하는 테스트를 둔다.** 술어를 비워도 테스트 전량이 통과하면 그 술어는 감시 밖이다 — `grep -rn <술어 이름> tests/`가 0건이면 계약이 없는 것이다.

## 검증 방법

검증기를 추가하거나 고칠 때 셋을 실행한다.

1. 통과 조건의 **여집합에서** 입력을 만든다. 정규식이면 문자 집합을 직접 읽고 "여기 무엇이 들어갈 수 있는가"를 센다 — 거절 사례 목록을 다시 읽지 않는다.
2. 검증기가 막으려는 실패를 한 문장으로 적고, 그 문장에 해당하는 입력이 통과하는지 본다.
3. 통과한 입력을 **끝까지 흘려** 최종 관측값을 본다. 형태 검증만 보면 침묵이 안 보인다 — 게이트를 실제로 돌려 exit code와 보고한 개수를 읽는다.

```bash
node -e 'import("./scripts/workspace-roots.mjs").then(m => {
  for (const g of ["*/*", "**/*", "pack?ges/*", "[ap]ps/*"])
    try { m.workspacePackageDirectories(process.cwd(), [g]); console.log(g, "통과(결함)"); }
    catch { console.log(g, "throw OK"); }
})'
```

판정 술어가 감시 밖인지는 참조 수로 본다.

```bash
grep -rn HEADLESS_FORBIDDEN tests/   # 0건이면 술어를 비워도 아무도 잡지 못한다
```

## 실제 근거

- 2026-08-23 Issue #107·#108 (`f41d728`, `e007e65`) — 같은 브랜치가 만든 통과 조건 안에서 게이트 구멍 넷이 나왔다. `*/*`가 형태 검증을 통과해 `check-licenses.mjs`가 `0 manifests`로 exit 0을 냈고(BLOCKER), 매니페스트 파서가 목록 중간 주석에서 멈춰 뒤 항목을 버렸고, `HEADLESS_FORBIDDEN`을 참조하는 테스트가 0건이라 술어를 `[]`로 비워도 `tests/` 124개가 전부 통과했고(격리 사본에서 `packages/io`에 `react`를 넣으니 게이트가 위반을 한 줄도 내지 않았다), 게이트 호출부가 `packagePaths`로 headless 검사 범위를 좁혀도 아무도 잡지 못했다.
- 넷 다 "거절 목록은 확인했고 통과 조건의 면적은 확인하지 않았다"라는 하나의 원인에서 나왔다.
