# PIT-0035 copy-detection 스캔 0건은 사본 없음의 증명이 아니다

- 상태: `ACTIVE`
- 적용 조건: 배열 리터럴 토큰 겹침으로 제품 판단 목록의 사본을 탐지하는 계약 테스트 결과 판독
- 지배 가이드: [`G-WKS-004`](../guides/G-WKS-004-verify-lint-and-gate-changes.md)
- 반복 근거: Issue #107·#108 — 세 번의 축 추가에서 세 번 다 자기 fixture·무관 파일이 걸리거나 사각지대가 남음 (PIT-0025 후속)

## 오해하기 쉬운 신호

표기 기반 탐지(하나의 배열 리터럴 안에 판정 토큰이 임계값 이상 모였는가)는 중첩 대괄호, 객체 값, `.split()`, 변수 경유로 만든 목록을 전부 0점으로 판정한다 — 이 계약을 통과했다고 사본이 없다는 뜻은 아니다. 반대 방향 오판도 있다 — 스캔에 걸린 결과가 전부 진짜 사본은 아니다. 계약 테스트 자신의 기대값 배열, 다른 테스트의 무관한 `it.each` fixture, 토큰을 원문 그대로 인용한 한국어 주석이 우연히 걸릴 수 있다.

## 원인

판정이 의미가 아니라 표기를 본다. 토큰 수가 적을수록 우연한 동시 등장 확률이 커진다. 사전 스캔, 걸린 파일의 개별 판정과 표기 변경 규칙은 `G-WKS-004`가 소유한다.

## 탐지

```bash
pnpm exec vitest run tests/workspace-roots.test.ts
```

목록 token 축은 `tests/workspace-roots.test.ts`의 단독 소유 계약에 추가한다. 추적 source가 0건이 아닌지와 발견된 source 집합이 예상과 정확히 같은지를 함께 단언한다. 결과가 0건이어도 "사본이 없다"로 보고하지 않고 "이 탐지기의 표기 기반 사각지대 안에서 0건"으로 보고한다. 새 표기 가능성을 조사하려고 일회성 scan이 필요하면 저장소 밖에서 실행하고 트리에 남기지 않는다([`G-PRC-001`](../guides/G-PRC-001-keep-scratch-work-outside-the-repository.md)).
