# 도메인 문서

에이전트가 Geul의 도메인 문서를 탐색하고 출력에 적용하는 규칙이다.

## 문서 구조

이 저장소는 single-context 구조를 사용한다.

```text
/
├── CONTEXT.md
├── docs/adr/
└── packages/
    ├── model/
    ├── io/
    ├── core/
    └── react/
```

`packages/model`, `io`, `core`, `react`는 별도 업무 도메인이 아니다. 하나의 Geul 제품 문맥을 구성하는 아키텍처 계층이므로 루트 공통 언어와 전역 ADR을 함께 사용한다.

실제로 독립된 제품 문맥이 생기기 전에는 `CONTEXT-MAP.md`나 패키지별 `CONTEXT.md`를 만들지 않는다.

## 탐색 전에 읽을 문서

- 루트 `CONTEXT.md`: 프로젝트 고유 용어와 피해야 할 혼동 표현
- 관련 `docs/adr/`: 장기 아키텍처 결정과 선택 이유

파일이 없으면 그 사실만으로 생성을 제안하지 않고 작업을 계속한다. 새 표준 용어나 장기 결정이 실제로 확정될 때 필요한 문서를 갱신한다.

전체 작업 시작 순서는 `AGENTS.md`, 문서 생성과 갱신 시점은 `docs/process/development-lifecycle.md`를 따른다.

## 공통 언어 사용

Issue 제목, spec, 리팩터링 제안, 가설과 테스트 이름에서 도메인 개념을 사용할 때 `CONTEXT.md`의 표준 용어를 사용한다. `_Avoid_`에 기록된 표현으로 의미를 흐리지 않는다.

필요한 개념이 공통 언어에 없다면 프로젝트가 사용하지 않는 표현을 새로 만든 것인지 먼저 확인한다. 실제 의미 공백이면 사용자와 정의를 확정한 뒤 `CONTEXT.md`를 갱신한다.

## ADR 충돌 처리

제안이 기존 ADR과 충돌하면 조용히 덮어쓰지 않는다. 충돌하는 ADR, 다시 검토할 이유, 영향 범위와 필요한 결정을 명시한다.

장기 결정이 바뀌면 과거 ADR을 삭제하거나 이유를 다시 쓰지 않는다. 새 ADR을 추가하고 기존 ADR의 상태를 대체됨으로 변경한다.
