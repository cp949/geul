작업 폴더 `$1`의 최종 결과를 정리한다. 이 세션에 앞선 맥락이 없다고 가정하고 작업 폴더의 문서와 git 이력만으로 재구성한다.

## 전제

작업 폴더 해석은 `AGENTS.md`의 "로컬 작업공간"을 따른다. 다음이 어긋나면 정지한다.

```
에러: meta.md 상태가 병합 완료가 아니다 — 현재 상태: <상태>
      /merge-dev를 먼저 실행해야 한다.

에러: implementation-report.md가 없다 — <경로>
```

## 절차

1. `meta.md`(확정 커밋 해시 포함), `implementation-report.md`, `handoff/*.md`의 `## 리뷰 결과` 섹션을 모두 읽는다.
2. `gh issue view <번호> --comments`로 이슈의 완료 기준과 체크리스트를 읽는다.
3. `git show --stat <확정 해시>`로 실제 변경을 대조한다. 문서가 주장하는 범위와 다르면 실측을 따르고 차이를 적는다.
4. `final-report.md`를 쓴다. 형식은 `AGENTS.md`의 "완료 보고"를 따른다.
   - 확인된 사실과 아직 검증하지 않은 가정
   - 변경한 계약과 파일
   - RED/GREEN 또는 재현/해결 증거
   - 실행한 검증과 결과
   - 남은 제한, 위험과 후속 이슈 초안
   - commit, merge, push와 PR의 실제 수행 여부
   - 확정 커밋 해시와 제목 목록
5. 그 내용으로 대상 이슈의 완료 댓글 초안을 `pending-issues/NN-issue<번호>-완료.md`에 만든다. 형식은 `docs/agents/issue-tracker.md`의 "게시 승인"을 따른다(`종류: 댓글`, `대상: #<번호>`, `상태: 미등록`).
6. `meta.md` 상태를 `보고 완료`로 바꾸고 진행 로그에 한 줄 덧붙인다.

## 규칙

- 이슈 완료 기준 중 충족하지 못한 항목이 있으면 충족한 것처럼 쓰지 않는다. 미충족으로 적고 이유와 남은 조치를 쓴다.
- 검증을 실행하지 않았으면 "실행하지 않음"으로 적는다. 이전 세션의 결과를 이 세션이 실행한 것처럼 쓰지 않는다.
- 확정 커밋 해시 외의 해시를 쓰지 않는다.
- GitHub에 쓰지 않는다. 게시는 `/issue-publish`가 한다.

보고: `final-report.md` 경로, 생성한 댓글 초안 경로, 미충족 완료 기준.
