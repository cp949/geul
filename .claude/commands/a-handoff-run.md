작업 폴더 `$1`의 핸드오프를 실행한다. 이 세션에 앞선 맥락이 없다고 가정하고 필요한 문서를 직접 읽는다.

이 커맨드는 **subagent 협업 모드**로 실행한다. 메인 세션은 조율·판단·커밋만 하고 리뷰와 수정은 subagent에 위임한다. 모드 규칙은 `docs/agents/a-workflow.md`의 "subagent 협업 모드"가 소유한다.

## 전제

작업 폴더 해석은 `docs/agents/a-workflow.md`의 "로컬 작업공간"을 따른다. 다음이 어긋나면 정지한다.

```
에러: meta.md가 없다 — <경로>

에러: 핸드오프가 없다 — <경로>/handoff/
      /a-handoff-write를 먼저 실행해야 한다.

에러: 최신 핸드오프가 이미 처리됐다 — handoff/NN.md (상태: 리뷰 완료)
      새 리뷰가 필요하면 /a-handoff-write로 다음 핸드오프를 만들어야 한다.

에러: 작업 브랜치가 없다 — <브랜치명>
      meta.md가 가리키는 브랜치가 삭제됐거나 이름이 다르다.

에러: 작업 트리가 깨끗하지 않다 — git status --short 출력 <N>줄
      2단계 git switch가 실패한다. 기존 변경은 사용자 작업이므로
      되돌리거나 stash하지 않고 사용자에게 처리를 묻는다.
```

## 절차

1. `meta.md`와 `handoff/`에서 번호가 가장 큰 파일을 읽는다. 그 파일의 상태가 `리뷰 대기`여야 한다.
2. `git switch <작업 브랜치>`로 이동하고 `git status --short`를 확인한다.
3. `AGENTS.md`의 "작업 시작 순서"와 대상 이슈(`gh issue view <번호> --comments`), `implementation-report.md`를 읽는다.
4. 핸드오프의 리뷰 초점과 미해결 항목을 갈래로 나눠 리뷰 subagent에 하나씩 위임한다. 읽기 전용으로 병렬 dispatch하고, 각 프롬프트에 담당 초점, 변경 범위(`git diff dev...<작업 브랜치>`), 읽어야 할 문서 경로와 반환 형식(결함마다 파일 경로·줄 번호, 재현 조건, 근거, 심각도)을 준다. 메인 세션이 보고를 합쳐 중복을 제거하고 진짜 결함인지 직접 확인한다. 초점 밖이어도 발견한 결함은 함께 다룬다.
5. 결함 수정은 수정 subagent에 하나씩 순차 위임한다 — 작업 트리를 공유하므로 동시에 띄우지 않는다. 각 수정은 회귀 테스트를 먼저 추가해 RED를 확인한 뒤 GREEN 구현을 한다. 기존 테스트를 지우거나 assertion을 약화해 통과시키지 않는다. subagent가 실행한 테스트 명령과 출력을 함께 받아 메인 세션이 확인한다.
6. 수정 커밋은 메인 세션이 같은 작업 브랜치에 이어 쌓는다. 새 브랜치를 만들지 않는다.
7. 변경 범위 focused 검증을 실행한다.
8. 읽은 핸드오프 파일 하단에 `## 리뷰 결과` 섹션을 덧붙인다 — 발견 항목, 수정 내용, 남은 위험, 실행한 검증과 결과. 파일 상태를 `리뷰 완료`로 바꾼다.
9. `meta.md` 상태를 `리뷰 완료`로 바꾸고 진행 로그에 한 줄 덧붙인다.

`/a-final-report`가 이 리뷰 결과 섹션을 읽어 최종 보고를 만든다. 여기 적지 않은 판단은 이후 세션에 전달되지 않는다.

## 정지 조건

squash, `dev` 병합, push, GitHub 쓰기를 하지 않는다. 현재 범위 밖에서 발견한 항목은 `pending-issues/`에 초안으로 남긴다. 커밋 해시를 문서에 쓰지 않는다.
