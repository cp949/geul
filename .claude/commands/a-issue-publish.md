인자: `$1`(선택). 지정하면 그 작업 폴더의 초안만, 없으면 `_works/*/pending-issues/*.md` 전체를 대상으로 한다. 게시 계약은 `docs/agents/issue-tracker.md`의 "게시 승인"이 원본이다.

## 전제

작업 폴더 해석은 `docs/agents/a-workflow.md`의 "로컬 작업공간"을 따른다.

**`final-report.md`가 있는 작업 폴더의 초안만 등록한다.** 등록은 상태 전이의 마지막 단계이고, `docs/agents/a-workflow.md`가 "각 단계는 앞 단계 산출물이 있어야 시작한다"로 정한 앞 단계 산출물이 `final-report.md`다. 없이 등록하면 두 가지가 깨진다.

- `/a-final-report`가 만드는 **이슈 완료 댓글 초안이 아직 없다.** 지금 등록하면 그 초안이 뒤늦게 따로 올라가 등록이 두 번으로 쪼개진다.
- 초안이 참조하는 확정 커밋 해시를 `/a-final-report`가 실측과 대조하기 **전**이다.

인자로 작업 폴더를 지정했는데 `final-report.md`가 없으면 아무것도 등록하지 않고 정지한다.

```
정지: final-report.md가 없다 — <경로>
      /a-final-report를 먼저 실행해야 한다. 현재 meta.md 상태: <상태>
```

인자 없이 전체를 대상으로 할 때는 그 작업 폴더만 건너뛰고 나머지는 진행한다. 건너뛴 폴더와 이유를 보고에 적는다.

## 절차

1. 대상 초안을 모은다. 위 전제를 통과한 작업 폴더에서 `상태: 미등록`인 것만 대상이다. 하나도 없으면 그 사실을 보고하고 정지한다.
2. 미푸시 커밋을 확인한다. `origin/dev`가 없으면 `git log origin/dev..dev`는 `fatal: 애매한 인자`로 exit `128`을 낸다. 존재를 먼저 확인한다.

   ```bash
   git rev-parse --verify --quiet origin/dev && git log --oneline origin/dev..dev
   ```

   `git rev-parse`가 실패하면(exit `1`) `dev`가 한 번도 push되지 않은 것이다. 등록하지 않고 정지한다.

   ```
   정지: origin/dev가 없다. dev를 한 번도 push하지 않았다.
         초안이 참조하는 커밋 해시에 GitHub에서 도달할 수 없다.
         push 후 다시 실행해야 한다. push는 지시가 필요하다.
   ```

   `git log` 출력이 비어 있지 않으면 등록하지 않고 정지한다. 초안이 참조하는 커밋 해시가 origin에 없으면 GitHub에서 링크가 깨진다.

   ```
   정지: dev에 미푸시 커밋 <N>개가 있다.
         push 후 다시 실행해야 한다. push는 지시가 필요하다.
   ```

3. 초안 목록과 **종료 예정 목록**을 사용자에게 제시한다. 초안은 파일 경로, 종류(신규 이슈/댓글), 대상 이슈 번호, 제목. 종료 예정은 아래 "종료 판단"으로 미리 판단한 이슈 번호와 그 근거 한 줄. 확인을 받은 뒤 등록한다.
4. 종류별로 등록한다. 본문은 임시 파일과 `--body-file`을 쓴다.

   ```bash
   gh issue create --title "<제목>" --body-file <경로>
   gh issue comment <번호> --body-file <경로>
   ```

   초안의 frontmatter는 본문에서 제외한다.
5. 등록에 성공한 초안의 `상태`를 `등록됨 #<번호>`로 갱신한다. 파일을 지우지 않는다.
6. 한 작업 폴더의 초안이 모두 등록되면 그 폴더의 `meta.md` 상태를 `등록 완료`로 바꾸고 진행 로그에 한 줄 덧붙인다.
7. 아래 "종료 판단"으로 대상 이슈를 닫는다. 3단계에서 승인받은 범위만 닫는다. 등록 결과가 3단계 판단과 달라졌으면(등록 실패, 남은 미등록 초안) 다시 판단해 좁힌다.

## 종료 판단

닫을지는 스스로 판단한다. 근거는 `final-report.md`와 이슈 본문의 완료 기준이고, 사용자에게 되묻지 않는다.

**모두 참이면 닫는다.**

- 이 실행에서 그 이슈에 `/a-final-report`가 만든 **완료 댓글**을 등록했다.
- `final-report.md`에 미충족 완료 기준이 없다. "실행하지 않음"으로 적힌 검증도 미충족으로 센다.
- 그 이슈를 대상으로 하는 `상태: 미등록` 초안이 더 남아 있지 않다.
- 이슈가 열려 있다.

**하나라도 거짓이면 닫지 않는다.**

경계 사례는 다음처럼 처리한다.

| 상황 | 처리 |
| --- | --- |
| 완료 기준은 모두 충족했고 후속 작업이 남았다 | 후속이 별도 이슈로 분리돼 있으면(이미 등록됨이거나 이번 실행에서 등록한 신규 이슈) 닫는다. 분리되지 않았으면 닫지 않는다 |
| 등록한 것이 정정 댓글이다 | 정정 후 기준이 모두 충족이면 닫는다 |
| 이슈가 이미 닫혀 있다 | 아무것도 하지 않는다. 다시 열지 않는다 |
| 열린 sub-issue가 있다 | 닫지 않는다 |
| 판단이 서지 않는다 | 닫지 않는다. 무엇이 불확실한지 보고에 적는다 |

sub-issue는 다음으로 확인한다. 목록이 비었거나 엔드포인트가 없으면(exit 비정상) 이슈 본문의 task list로 대신 본다.

```bash
gh api repos/<owner>/<repo>/issues/<번호>/sub_issues --jq '.[] | select(.state == "open") | .number'
```

종료는 댓글 없이 상태만 바꾼다. 종료 사유는 4단계가 등록한 완료 댓글이 소유한다.

```bash
gh issue close <번호>
```

## 금지

- 초안에 없는 내용을 새로 만들어 올리지 않는다. 내용 생성은 `/a-issue-work`, `/a-handoff-run`, `/a-final-report`가 한다. 이 커맨드는 게시만 한다.
- 완료 댓글을 등록하지 않은 이슈를 닫지 않는다. 종료는 완료 보고에 딸린 상태 전이이지 독립 조치가 아니다.
- 닫으면서 새 댓글을 만들어 붙이지 않는다. `gh issue close --comment`를 쓰지 않는다.
- 닫힌 이슈를 다시 열지 않는다.
- 라벨, assignee, sub-issue와 dependency를 초안이 명시하지 않은 범위에서 바꾸지 않는다.
- push하지 않는다.

보고: 등록한 이슈 번호와 URL, 갱신한 초안 경로, 닫은 이슈 번호, 닫지 않은 대상 이슈와 그 이유, 건너뛴 초안·작업 폴더와 이유.
