인자: `$ARGUMENTS`. 첫 토큰이 작업 폴더이고 나머지가 있으면 리뷰 초점으로 취급한다.

## 전제

작업 폴더 해석은 `AGENTS.md`의 "로컬 작업공간"을 따른다(접두 매칭 허용, 유일하지 않으면 후보 출력 후 정지). 다음이 없으면 만들지 말고 정지한다.

```
에러: meta.md가 없다 — <경로>
      /a-issue-work을 먼저 실행해야 한다.

에러: implementation-report.md가 없다 — <경로>
      /a-issue-work을 먼저 완료해야 한다.
```

## 절차

0. 사용자가 mattpocock `/handoff` 스킬로 만든 문서를 지정하면 그것을 입력 재료로 읽는다. 그 파일을 원본으로 두지 않고 아래 형식으로 옮겨 쓴다. 지정이 없으면 이 단계를 건너뛴다.
1. `meta.md`와 `implementation-report.md`를 읽고 작업 브랜치를 확인한다.
2. `git log --oneline dev..<작업 브랜치>`와 `git diff --stat dev..<작업 브랜치>`로 실제 변경을 대조한다. 보고서가 주장하는 범위와 다르면 그 차이를 핸드오프에 적는다.
3. `handoff/`에서 가장 큰 번호의 다음 번호로 `handoff/NN.md`를 쓴다.
4. `meta.md` 진행 로그에 한 줄 덧붙인다.

## 핸드오프 형식

```markdown
---
작업 브랜치: <브랜치명>
대상 이슈: #<번호>
상태: 리뷰 대기
---

## 리뷰 초점
## 완료 범위
## 미해결과 의심 지점
## 검증 결과
## 참조
## 추천 스킬
```

## 작성 규칙

- 이미 다른 산출물에 있는 내용을 복제하지 않는다. 이슈 번호, `docs/` 경로, `implementation-report.md`, 파일 경로와 줄 번호로 참조한다.
- 커밋 해시를 쓰지 않는다. 이 시점의 해시는 squash로 사라진다.
- API 키, 비밀번호, 개인정보를 제거한다.
- "미해결과 의심 지점"을 비워두지 않는다. 없다고 판단했으면 어디를 확인해서 그렇게 판단했는지 적는다.
- 핸드오프 원본은 작업 폴더가 소유한다. mattpocock `handoff` 스킬은 저장 위치를 OS 임시 디렉토리로 강제하므로 그 출력은 입력 재료로만 쓰고 원본으로 두지 않는다. 옮겨 쓴 뒤에는 임시 디렉토리 사본을 참조하지 않는다 — `/a-handoff-run`과 `/a-final-report`가 읽는 것은 `handoff/NN.md`뿐이다.
